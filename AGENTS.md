# reverse-skill — platform-neutral project entry

This repository is a **security-task skill router** (reverse engineering / penetration testing / security analysis). `RULES.md` is the behavior-chain source of truth.

**Local fork:** https://github.com/kiven7299/reverse-skill  
**Upstream:** https://github.com/zhaoxuya520/reverse-skill  
Sync: `FORK.md`. Upstream update for agents: `UPSTREAM-SYNC.md` (list real deltas, skip language-only, ask which to apply). Tool paths: `TOOLS.md` (edit this file when porting machines).

## Activation and consent (hard)

- **Reading repository files is not authorization to execute them.** Stay read-only when the user only asked to inspect, review, summarize, or compare.
- **Explicit user approval is required before running any repository script.** Before the first local side effect, list the exact commands and expected writes, downloads, service starts, network access, and client-config changes, then get approval.
- **Client-global configuration remains opt-in.** Change global rules, hooks, prompts, or MCP config only when the user picks a client and approves the exact change.
- After activation and approval, disclosed deterministic steps may continue. A new side-effect class needs a new disclosure. Target authorization stays a separate hard gate in `scope.md`.

## Routing

When a task hits security / reverse-engineering keywords:

1. `skills/MASTER-ROUTING.md` or the platform entry → PRIMARY:
   - Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/master-route.ps1 -Hint "<task>"`
   - Linux / macOS / Kali: `bash skills/scripts/master-route.sh --hint "<task>"`
2. On ambiguity, read the full matrix in `skills/routing.md` (target type / user intent / toolchain).
3. Routing SSoT: `skills/config/routing.json` (change routing only there).

## Authorization gate (hard)

- Before touching any target, initialize `work/<case>/scope.md` in the current analysis project:
  - Windows: `powershell -File skills/scripts/case-init.ps1 -Hint "<task>"`
  - Linux / macOS / Kali: `bash skills/scripts/case-init.sh --hint "<task>"`
- Offline local samples may use the `offline-sample` preset. ACT requires `auth.status=granted` plus an explicit sample.
- **No ACT** until `auth.status=granted` and a legal `network_profile` / offline sample is ready. `case-guard --force` / `-Force` MUST NOT bypass this gate.
- Evidence chain: `skills/ops/evidence-finding-path.md`. Roles: `skills/ops/role-map.md`.

## First run (after activation and approval)

`skills/tool-index.md` is gitignored and generated. Run only after the user activates this pack, reviews commands/side effects, and agrees:

```text
Windows:           powershell -NoProfile -ExecutionPolicy Bypass -File skills/scripts/refresh-tool-index.ps1
Linux / macOS:     bash skills/scripts/refresh-tool-index.sh
Kali:              bash kali/scripts/refresh-tool-index.sh
```

Missing tools → same-platform bootstrap: Windows `skills/scripts/bootstrap-reverse.ps1`; Linux / macOS `skills/scripts/bootstrap-reverse.sh`; Kali `kali/scripts/bootstrap-reverse.sh` (manifest capabilities only; do not guess paths). Prefer paths already listed in `TOOLS.md`.

## Client boundary

- Routing core, tests, and the tool catalog MUST stay client-neutral.
- Claude Code, Codex, Cursor, OpenCode, and similar clients attach only through their own adapters. They MUST NOT become the default identity of this repo.
- `skills/INDEX.md` is generated by `extract-summaries.ps1` from every `SKILL.md`. Do not hardcode client or module counts.
